# Agent 工作台模块

本模块使用官方 `agentscope-harness:2.0.3` 的 Harness/ReAct 执行循环、工具历史、会话状态和 `todo_write` 任务列表。模型决定调用顺序；没有按页面或用户关键词分派业务意图的代码。

## 依赖方向

```text
system-admin（Spring Boot 装配与业务适配）
  -> system-agent（执行、会话、事件、事务回执）
      -> AgentScope Harness / OpenAI formatter
      -> Spring JDBC / Transaction
```

`system-agent` 不依赖 `system-admin`、`system-framework`、`common-core`、MyBatis、Servlet 或 Spring Security。业务身份、权限和租户由装配端负责，不能把用户发来的 userId / tenantId 当作 `AgentActor`。

## 接入端口

- `AgentPromptGateway`：从已有提示词配置读取启用的 Agent 场景，并绑定已有模型配置。提示词和模型配置不在本模块重复管理。
- `AgentModelGateway`：持有现有供应商路由、Key 选择、超时、价格约束及完整请求日志。交互是 OpenAI JSON 流；模块不持有 Key、供应商 URL 或 HTTP 客户端。
- `AgentResourceGateway`：注册资源和动态字段，提供发现、描述、查询、写入/批量操作。适配器每次重新检查账号状态、权限、租户、字段校验及记录版本；不能依赖 HTTP 请求线程遗留的认证上下文。
- `AgentHistoryAccess`：历史会话、事件、模型下一轮输入重新核对已使用资源的权限。业务适配器还应实施其记录范围约束。
- `AgentPayloadCodec`：由应用提供带 purpose 绑定的加密。SDK 状态、输入、事件及工具回执先加密再存储，没有生产用明文默认实现。

SDK 的 web / 文件 / Shell / workspace 插件工具不属于后台业务能力，从原生工具注册表移除；业务扩展通过资源适配器进行。默认追踪日志关闭，公开事件只包含文本、工具状态、使用量及任务步骤，不包含 ThinkingBlock 或隐藏系统提示词。

## 持久化和执行

- `V20261024_400__agent_workbench.sql` 由本模块维护六张独立表；不修改业务表。
- 提交使用客户端请求标识；相同标识和内容只创建一次任务。轮询/重连事件接口不会重新调用模型。
- 同会话串行准入，后台执行器为一个工作线程及八项队列。原生模型重试预算为一次尝试，供应商切换由现有网关决定。
- 业务写入和工具回执处于同一数据库事务，避免同一工具调用重复执行；异常会回滚业务变更。
- SDK 状态支持 CAS，并绑定用户、租户、会话。旧任务不能覆盖下一任务的状态。
- 取消同时停止外层循环和静默模型流；过期任务标为中断，重启/重连不会自动重放写操作。
- 所有状态读写必须使用同一 Spring 事务管理器/数据源，业务适配器不得另开独立事务提交同一写操作。

## 当前验证与待接线

模块可独立编译并通过11项受控测试：官方工具循环、Todo 面板、权限错误、持久多轮历史、并发提交去重、写入回执/事务回滚、历史权限变更、租户隔离、CAS、静默流取消等。测试模型与数据均为虚构，没有发送真实业务数据。

`system-admin` 已聚合本模块依赖并提供复用现有主密钥的会话加密适配；Agent 系统提示词由既有提示词管理保存版本。现有供应商网关已支持工具调用传输，MiMo V2.6 Flash 原生虚构工具往返通过。模型仍保持一模型一卡片，多供应商接入在同一模型内部维护；不同模型的调用顺序属于场景路由。

工作台后台服务的生产装配、业务资源适配器、模型/日志桥接、HTTP 控制器与正式前端页面仍待完成。不能用单独传输测试或阶段提交代替完整 AI 工作台验收。
