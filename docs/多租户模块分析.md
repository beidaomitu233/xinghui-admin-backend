# 多租户模块分析

## 一、模块概述

RuoYi-Vue-Plus 的多租户模块基于 **MyBatis-Plus 租户插件** + **ThreadLocal 上下文** + **Redis 隔离** 实现全方位的多租户支持。

### 1.1 模块位置

```
ruoyi-common-tenant/
├── config/TenantConfig.java              # 租户自动配置类
├── helper/TenantHelper.java              # 租户上下文管理核心工具类
├── handle/PlusTenantLineHandler.java     # MyBatis-Plus 租户SQL拦截处理器
├── handle/TenantKeyPrefixHandler.java    # Redis Key 租户前缀处理器
├── core/TenantEntity.java                # 租户实体基类
├── core/TenantSaTokenDao.java            # 多租户鉴权数据持久层
├── manager/TenantSpringCacheManager.java # 多租户缓存管理器
├── properties/TenantProperties.java      # 租户配置属性
└── exception/TenantException.java        # 租户异常类
```

### 1.2 技术栈

- **MyBatis-Plus TenantLineInnerInterceptor**（SQL 租户拦截）
- **ThreadLocal**（线程级租户上下文）
- **Redis**（全局租户切换、Key 前缀隔离）
- **Sa-Token**（鉴权数据租户隔离）

## 三、SQL 层租户隔离

### 3.1 插件注册顺序

**文件位置**: `ruoyi-common-mybatis/config/MybatisPlusConfig.java`

```java
@Bean
public MybatisPlusInterceptor mybatisPlusInterceptor() {
    MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
    // 多租户插件 必须放到第一位 (最关键)
    try {
        TenantLineInnerInterceptor tenant = SpringUtils.getBean(TenantLineInnerInterceptor.class);
        interceptor.addInnerInterceptor(tenant);
    } catch (BeansException ignore) {
    }
    // 数据权限 -> 分页 -> 乐观锁
    interceptor.addInnerInterceptor(dataPermissionInterceptor());
    interceptor.addInnerInterceptor(paginationInnerInterceptor());
    interceptor.addInnerInterceptor(optimisticLockerInnerInterceptor());
    return interceptor;
}
```

**关键点**: 租户插件必须放在拦截器链的**第一位**，确保在执行其他拦截器之前先处理租户条件。

### 3.2 PlusTenantLineHandler（租户行处理器）

```java
public class PlusTenantLineHandler implements TenantLineHandler {

    @Override
    public Expression getTenantId() {
        String tenantId = TenantHelper.getTenantId();
        if (StringUtils.isBlank(tenantId)) {
            log.error("无法获取有效的租户id -> Null");
            return new NullValue();  // 获取不到租户ID时返回NULL
        }
        return new StringValue(tenantId);  // 返回固定租户ID
    }

    @Override
    public boolean ignoreTable(String tableName) {
        String tenantId = TenantHelper.getTenantId();
        if (StringUtils.isNotBlank(tenantId)) {
            // 不需要过滤租户的表 (配置排除表 + 非业务表)
            List<String> excludes = tenantProperties.getExcludes();
            List<String> tables = ListUtil.of("gen_table", "gen_table_column");
            tables.addAll(excludes);
            return StringUtils.equalsAnyIgnoreCase(tableName, tables.toArray(new String[0]));
        }
        return true;  // 没有租户ID时，所有表都忽略租户过滤
    }
}
```

## 四、租户上下文管理（TenantHelper）

### 4.1 核心数据结构

```java
// 动态租户在Redis中的Key前缀
private static final String DYNAMIC_TENANT_KEY = GlobalConstants.GLOBAL_REDIS_KEY + "dynamicTenant";

// 线程内动态租户 (未登录或非全局模式时使用)
private static final ThreadLocal<String> TEMP_DYNAMIC_TENANT = new ThreadLocal<>();

// 可重入忽略策略栈
private static final ThreadLocal<Stack<Integer>> REENTRANT_IGNORE = ThreadLocal.withInitial(Stack::new);
```

### 4.2 租户 ID 获取优先级

```java
public static String getTenantId() {
    // 1. 优先获取动态租户 (支持租户切换)
    String tenantId = TenantHelper.getDynamic();
    // 2. 如果没有动态租户，获取登录用户的租户
    if (StringUtils.isBlank(tenantId)) {
        tenantId = LoginHelper.getTenantId();
    }
    return tenantId;
}
```

**优先级**: 动态租户 > 登录用户租户

### 4.3 动态租户设置流程

```java
public static void setDynamic(String tenantId, boolean global) {
    if (!LoginHelper.isLogin() || !global) {
        // 未登录或非全局模式: 只在线程内生效
        TEMP_DYNAMIC_TENANT.set(tenantId);
        return;
    }
    // 已登录且全局模式: 写入Redis和Sa-Token存储
    String cacheKey = DYNAMIC_TENANT_KEY + ":" + LoginHelper.getUserId();
    RedisUtils.setCacheObject(cacheKey, tenantId);
    SaHolder.getStorage().set(cacheKey, tenantId);
}
```

### 4.4 三种租户操作模式

```java
// 模式 1: 临时切换（自动清理）
TenantHelper.dynamic("newTenantId", () -> {
    // 在此块内所有 SQL 使用新租户 ID
    userService.list();
});

// 模式 2: 手动设置（需手动清理）
TenantHelper.setDynamic("newTenantId", true);  // 全局生效
// ... 业务操作 ...
TenantHelper.clearDynamic();

// 模式 3: 忽略租户
TenantHelper.ignore(() -> {
    // 在此块内 SQL 不带租户条件
    tenantService.queryList(bo);  // 可查询所有租户数据
});
```

### 4.5 忽略租户机制

```java
// 开启忽略租户
private static void enableIgnore() {
    IgnoreStrategy ignoreStrategy = getIgnoreStrategy();
    if (ObjectUtil.isNull(ignoreStrategy)) {
        InterceptorIgnoreHelper.handle(IgnoreStrategy.builder().tenantLine(true).build());
    } else {
        ignoreStrategy.setTenantLine(true);
    }
    Stack<Integer> reentrantStack = REENTRANT_IGNORE.get();
    reentrantStack.push(reentrantStack.size() + 1);  // 支持可重入
}

// 在忽略租户中执行 (自动清理)
public static void ignore(Runnable handle) {
    enableIgnore();
    try {
        handle.run();
    } finally {
        disableIgnore();
    }
}
```

**使用 MyBatis-Plus 内置的 `InterceptorIgnoreHelper` 实现忽略机制，支持可重入调用。**

## 五、Redis 多租户隔离

### 5.1 Key 前缀处理（TenantKeyPrefixHandler）

```java
@Override
public String map(String name) {
    // 忽略租户时不添加前缀
    if (InterceptorIgnoreHelper.willIgnoreTenantLine("")) {
        return super.map(name);
    }
    // 全局Key不添加租户前缀
    if (StringUtils.contains(name, GlobalConstants.GLOBAL_REDIS_KEY)) {
        return super.map(name);
    }
    String tenantId = TenantHelper.getTenantId();
    // 添加租户前缀: tenantId:name
    return super.map(tenantId + ":" + name);
}
```

**效果**:
```
原始Key: user:123
租户Key: 000000:user:123
```

### 5.2 缓存管理器（TenantSpringCacheManager）

```java
@Override
public Cache getCache(String name) {
    if (InterceptorIgnoreHelper.willIgnoreTenantLine("")) {
        return super.getCache(name);
    }
    if (StringUtils.contains(name, GlobalConstants.GLOBAL_REDIS_KEY)) {
        return super.getCache(name);
    }
    String tenantId = TenantHelper.getTenantId();
    // cacheName 添加租户前缀
    return super.getCache(tenantId + ":" + name);
}
```

### 5.3 Sa-Token 鉴权隔离（TenantSaTokenDao）

```java
@Override
public String get(String key) {
    // 所有鉴权Key都使用全局前缀，不区分租户
    return super.get(GlobalConstants.GLOBAL_REDIS_KEY + key);
}
```

**设计意图**: 鉴权数据是全局共享的，通过 Token 本身关联租户信息，不需要在 Key 中区分租户。

## 六、登录流程中的租户处理

### 6.1 登录流程

```
AuthController.login()
    ↓
loginService.checkTenant(tenantId)  // 校验租户是否存在/有效/未过期
    ↓
IAuthStrategy.login() -> PasswordAuthStrategy.login()
    ↓
TenantHelper.dynamic(tenantId, () -> {
    loadUserByUsername(username)  // SQL 自动带上 tenant_id 条件
    buildLoginUser(user)          // 构建登录用户，包含tenantId
})
    ↓
LoginHelper.login(loginUser, model)
    ↓
// Sa-Token 存储租户ID到Token的extra中
model.setExtra(TENANT_KEY, loginUser.getTenantId())
```

### 6.2 租户校验逻辑

```java
public void checkTenant(String tenantId) {
    if (!TenantHelper.isEnable()) return;
    
    if (StringUtils.isBlank(tenantId)) {
        throw new TenantException("tenant.number.not.blank");  // 租户ID不能为空
    }
    if (TenantConstants.DEFAULT_TENANT_ID.equals(tenantId)) {
        return;  // 默认租户直接通过
    }
    
    SysTenantVo tenant = tenantService.queryByTenantId(tenantId);
    if (ObjectUtil.isNull(tenant)) {
        throw new TenantException("tenant.not.exists");     // 租户不存在
    }
    if (SystemConstants.DISABLE.equals(tenant.getStatus())) {
        throw new TenantException("tenant.blocked");        // 租户已停用
    }
    if (new Date().after(tenant.getExpireTime())) {
        throw new TenantException("tenant.expired");        // 租户已过期
    }
}
```

### 6.3 登录后获取租户 ID

```java
public static String getTenantId() {
    return Convert.toStr(getExtra(TENANT_KEY));  // 从Token的extra中获取
}
```

### 6.4 登出时租户清理

```java
public void logout() {
    LoginUser loginUser = LoginHelper.getLoginUser();
    if (TenantHelper.isEnable() && LoginHelper.isSuperAdmin()) {
        // 超级管理员登出时清除动态租户
        TenantHelper.clearDynamic();
    }
    StpUtil.logout();
}
```

## 九、关键设计模式总结

| 模式 | 实现 |
|------|------|
| **策略模式** | `TenantLineHandler` 接口，可自定义租户处理逻辑 |
| **模板方法** | `TenantEntity` 作为基类，所有租户实体继承 |
| **拦截器模式** | `TenantLineInnerInterceptor` 自动拦截SQL |
| **上下文模式** | `ThreadLocal` + Redis 存储租户上下文 |
| **工厂模式** | `TenantConfig` 通过条件装配创建Bean |
| **装饰器模式** | `TenantSaTokenDao` 装饰原始DAO添加租户前缀 |

## 十、重要注意事项

1. **租户插件顺序**: 必须在 MyBatis-Plus 拦截器链的第一位
2. **全局Key标识**: 使用 `GlobalConstants.GLOBAL_REDIS_KEY = "global:"` 前缀的Key不参与租户隔离
3. **可重入忽略**: `REENTRANT_IGNORE` 使用栈结构支持嵌套调用
4. **动态租户优先级**: 动态租户 > 登录租户，支持超级管理员切换查看不同租户数据
5. **排除表设计**: 权限关联表、系统配置表不参与租户隔离
6. **租户ID生成**: 6位随机数字，需保证唯一性
