# 三方鉴权（JustAuth）模块分析

## 一、模块概述

RuoYi-Vue-Plus 基于 **JustAuth** (me.zhyd.oauth:JustAuth) 开源库实现第三方社交登录功能，采用策略模式 + 自动配置的设计思想，支持 25+ 第三方 OAuth2/OAuth 平台。

### 1.1 模块位置

```
ruoyi-common-social/
├── config/
│   ├── SocialAutoConfiguration.java          # Spring Boot 自动配置类
│   └── properties/
│       ├── SocialProperties.java             # 顶层配置属性 (justauth.*)
│       └── SocialLoginConfigProperties.java  # 单个平台配置属性
├── utils/
│   ├── SocialUtils.java                      # 核心工具类 - 创建 AuthRequest
│   └── AuthRedisStateCache.java              # Redis 状态缓存实现
├── topiam/
│   ├── AuthTopIamRequest.java                # TopIAM 自定义认证请求
│   └── AuthTopIamSource.java                 # TopIAM 平台端点定义
├── maxkey/
│   ├── AuthMaxKeyRequest.java                # MaxKey 自定义认证请求
│   └── AuthMaxKeySource.java                 # MaxKey 平台端点定义
└── gitea/
    ├── AuthGiteaRequest.java                 # Gitea 自定义认证请求
    └── AuthGiteaSource.java                  # Gitea 平台端点定义

覆盖 JustAuth 内置类:
├── me/zhyd/oauth/request/
│   ├── AuthDingTalkV2Request.java            # 新版钉钉认证请求
│   └── AbstractAuthWeChatEnterpriseRequest.java  # 企业微信抽象父类
```

### 1.2 技术栈

- **JustAuth**（me.zhyd.oauth:JustAuth v1.16.7）
- **Redis**（state 参数缓存、分布式锁）
- **Sa-Token**（统一鉴权）

### 4.3 AuthRedisStateCache（Redis 状态缓存）

```java
public class AuthRedisStateCache implements AuthStateCache {
    // 缓存 key 前缀: "global:social_auth_codes:"
    // 默认过期时间: 3 分钟

    @Override
    public void cache(String key, String value) {
        RedisUtils.setCacheObject(GlobalConstants.SOCIAL_AUTH_CODE_KEY + key, value, Duration.ofMinutes(3));
    }

    @Override
    public String get(String key) {
        return RedisUtils.getCacheObject(GlobalConstants.SOCIAL_AUTH_CODE_KEY + key);
    }

    @Override
    public boolean containsKey(String key) {
        return RedisUtils.hasKey(GlobalConstants.SOCIAL_AUTH_CODE_KEY + key);
    }
}
```

**作用**: 替代 JustAuth 默认的内存缓存，实现分布式环境下的 state 参数防 CSRF 攻击。

## 五、API 接口

### 5.1 AuthController 社交登录相关接口

| 接口 | 方法 | 路径 | 说明 | 是否需要登录 |
|------|------|------|------|:------------:|
| 获取绑定跳转 URL | GET | `/auth/binding/{source}` | 返回第三方 OAuth 授权 URL | 否 |
| 社交回调绑定 | POST | `/auth/social/callback` | 用户授权后绑定第三方账号 | **是** |
| 取消授权 | DELETE | `/auth/unlock/{socialId}` | 解绑第三方账号 | **是** |
| 统一登录 | POST | `/auth/login` | 支持 grantType=social 的第三方登录 | 否 |

### 5.2 获取绑定跳转 URL

```java
@GetMapping("/binding/{source}")
public R<String> authBinding(@PathVariable("source") String source,
                              @RequestParam String tenantId, @RequestParam String domain) {
    AuthRequest authRequest = SocialUtils.getAuthRequest(source, socialProperties);
    Map<String, String> map = new HashMap<>();
    map.put("tenantId", tenantId);
    map.put("domain", domain);
    map.put("state", AuthStateUtils.createState());  // 生成随机 state 防 CSRF
    String authorizeUrl = authRequest.authorize(Base64.encode(JsonUtils.toJsonString(map)));
    return R.ok("操作成功", authorizeUrl);
}
```

## 六、社交账号绑定/解绑流程

### 6.1 绑定流程（需要已登录）

```java
@Lock4j  // 分布式锁防止并发绑定
public void socialRegister(AuthUser authUserData) {
    String authId = authUserData.getSource() + authUserData.getUuid();

    // 1. 检查是否已被其他用户绑定
    List<SysSocialVo> checkList = sysSocialService.selectByAuthId(authId);
    if (CollUtil.isNotEmpty(checkList)) {
        throw new ServiceException("此三方账号已经被绑定!");
    }

    // 2. 检查当前用户是否已绑定该平台
    params.setUserId(userId);
    params.setSource(source);
    List<SysSocialVo> list = sysSocialService.queryList(params);

    if (CollUtil.isEmpty(list)) {
        // 首次绑定 - 新增记录
        sysSocialService.insertByBo(bo);
    } else {
        // 已存在 - 更新用户信息
        sysSocialService.updateByBo(bo);
    }
}
```

### 6.2 解绑流程（需要已登录）

```java
@DeleteMapping(value = "/unlock/{socialId}")
public R<Void> unlockSocial(@PathVariable Long socialId) {
    StpUtil.checkLogin();  // 必须已登录
    Boolean rows = socialUserService.deleteWithValidById(socialId);
    return rows ? R.ok() : R.fail("取消授权失败");
}
```

```java

String state = AuthStateUtils.createState();

callback.setState(state);
authRequest.login(callback);  // JustAuth 内部会验证 state 一致性
```

## 十、核心设计模式

### 10.1 策略模式 - 授权策略

```
IAuthStrategy (接口)
    ├── PasswordAuthStrategy  (password + BASE_NAME)
    ├── SmsAuthStrategy       (sms + BASE_NAME)
    ├── SocialAuthStrategy    (social + BASE_NAME)  <-- 第三方登录策略
    └── EmailAuthStrategy     (email + BASE_NAME)
```

通过 `IAuthStrategy.login(body, client, grantType)` 静态方法，根据 `grantType` 动态选择对应的策略 Bean。

### 10.2 工厂模式 - AuthRequest 创建

`SocialUtils.getAuthRequest()` 根据 `source` 参数创建不同的 `AuthRequest` 实例，是典型的简单工厂模式。

## 十一、自定义平台扩展方式

如果需要新增自定义 OAuth2 平台，需创建两个类：

### 11.1 AuthXxxSource（实现 AuthSource 接口）

```java
public enum AuthXxxSource implements AuthSource {
    XXX {
        @Override public String authorize() { return SERVER_URL + "/oauth/authorize"; }
        @Override public String accessToken() { return SERVER_URL + "/oauth/token"; }
        @Override public String userInfo() { return SERVER_URL + "/oauth/userinfo"; }
        @Override public Class<? extends AuthDefaultRequest> getTargetClass() { return AuthXxxRequest.class; }
    }
}
```

### 11.2 AuthXxxRequest（继承 AuthDefaultRequest）

```java
public class AuthXxxRequest extends AuthDefaultRequest {
    @Override public AuthToken getAccessToken(AuthCallback authCallback) { ... }
    @Override public AuthUser getUserInfo(AuthToken authToken) { ... }
}
```

### 11.3 注册新平台

在 `SocialUtils.getAuthRequest()` 的 switch 中添加新 case：

```java
case "xxx" -> AuthXxxRequest
```

## 十二、总结

该项目的 JustAuth 集成具有以下特点：

1. **模块化设计**: 社交登录功能独立为 `ruoyi-common-social` 模块
2. **自动配置**: 通过 Spring Boot AutoConfiguration 自动装配
3. **分布式支持**: 使用 Redis 存储 state，支持多实例部署
4. **多租户支持**: 社交账号与租户关联，支持租户隔离
5. **策略模式**: 通过 `IAuthStrategy` 接口实现多种登录方式统一入口
6. **可扩展性**: 自定义平台只需实现 `AuthSource` + `AuthRequest` 两个类
7. **安全性**: CSRF 防护、分布式锁、Token 校验、状态校验等多重安全机制
